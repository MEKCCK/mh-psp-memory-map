# 如何挖掘新的内存地址（方法论）

目标：为 MHF / MHF2 / MHFU / MHP3RD 找到**稳定、可验证**的内存地址，并标明版本与来源。

## 0. 核心概念（先读 memory-map.md 第 0 节）

- 一切地址是 **PSP 虚拟地址**，实体机 = PPSSPP（同版本同地址）。
- **绝对地址** 以 `0x08` / `0x09` 开头；真机 cheat 库给的是 **RAM 偏移**（+`0x08800000` 才是绝对地址）。
- 原版 `ULJM05800` 与 HD `NPJB40001` **布局不同**，分开挖、分开记录。

## 1. 工具准备

| 工具 | 用途 |
|---|---|
| PPSSPP（含内置 ImDebugger / 内存编辑器） | 直接读写 PSP 内存 + 中断观察 |
| WebSocket 调试器（`memory.read_u32` / `memory.search` / `memory.base`） | 脚本化搜索，Cheat Engine 式 |
| 已知 mod / loader 的反汇编（mhp3reload、p3rd_* 系列） | 借地址与结构线索 |
| Ghidra / IDA（MIPS，PSP 插件） | 对 EBOOT/解压后代码做函数考古 |
| 真机 cheat 库/CWCheat 表 | 交叉来源（注意偏移写法） |

## 2. 五种典型挖掘路线

### 方法一：从已知指针遍历结构体（最简单，推荐入门）

以怪物数据为例（P3，验证过的流程）：

1. 已知怪物列表指针 `0x09DA9860` → `lw ptr0` = 第一只怪。
2. 进任务打怪，逐字节观察 `ptr0` 所在结构体的变化区间（HP 掉、状态变）。
3. 对"当前 HP"做**数值追踪**：暂停模拟 → 改一个值 → 恢复 → 确认生效 → 记偏移。
4. 同法扩展：尺寸、异常状态当前值/阈值、怒计时。
5. 记下结构体基址与相对偏移；**另一只怪/另一个版本再验证一次**。

### 方法二：数值搜寻（无指针起点时）

用 WebSocket `memory.search`（支持 u8/u16/u32/float、范围、通配）：

1. 暂停游戏（`cpu.stepping`）。
2. 搜索当前值（如钱 `12345`）→ 缩小范围（花一点钱再搜）。
3. 命中后 `memory.read` 看上下文，识别结构。
4. 找到后**重启游戏**再验证是否稳定（地址是否固定：找稳定指针，而非每次变）。

### 方法三：指针链反推（地址每次变时）

若发现数据地址每次启动都变 → 找指针：从命中地址向上反查谁引用它
（`memory.search` 搜"指向该地址的 u32"），直到某个全局固定地址（`0x0880–0x09F0` 区内）持有链头。

### 方法四：代码考古（利用 mod/loader 的 hook）

1. 收集已有 mod 的 hook 地址（见 memory-map.md 第 6 节等）。
2. 在 Ghidra 里把 EBOOT（解压后主程序，位于 `0x08804000+`）加载成 MIPS/LE。
3. 从 hook 地址反追踪：谁调用了它、它读写哪些全局区 → 那些全局区就是新数据。
4. 例：`READ_HOOK` 附近能找到文件缓存结构；`+0x246/+0x288` 是怪物 HP 是被 mod 证明的。

### 方法五：文件表路线（结构性数据，如肉质/数值表）

1. 游戏资源按**文件索引表**组织（loader 的 `FILES/<hexid>` 机制，参考 modelloader）。
2. 用 `MHP3rd-Game-FIle-List` / PAC 工具（`psp_mh_pac_importer`、`pmo_export`）解包数据文件。
3. 找到肉质/怪物数值后，再定位运行时它被加载到哪个内存区（hook 读文件 → 数据缓存区）。

## 3. 版本与写法检查清单（提交前必过）

- [ ] 标明游戏（MHF/MHF2/MHFU/MHP3RD）与具体 Disc ID
- [ ] 标明版本（原版 ULJM05800 / HD NPJB40001，或"两版通用"）
- [ ] 地址是**绝对地址**（或以偏移表示并注明换算方式）
- [ ] 字段类型明确（u8/u16/u32/float、读写）
- [ ] 至少一次实机/模拟器验证（重启游戏后仍有效）
- [ ] （加分）第二个独立来源互证（我们 P3 的列表指针 `0x09DA9860`、HP `+0x246/0x288`
      就是 hpbar mod 与 orig Python overlay 互证的例子）
- [ ] 来源可溯源（哪个仓库/工具/会话挖的，给链接）
